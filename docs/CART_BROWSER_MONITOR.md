# Permanent live monitor

The [dark browser dashboard](https://ojaswi03.github.io/PaperMerge/) uses one
persistent `?feed=...` link. Share the complete link printed by the publisher.
The base page alone has no selected monitor.

## Start or select a run

Run this on hal9k while training continues:

```bash
cd ~/Masters_Research/PaperMerge
git pull --ff-only
source .venv-hpc/bin/activate

python scripts/share_cart_monitor.py \
  --output /var/tmp/papermerge-os675524/basil-sharp-thesis-direct-checked-100r-20261030 \
  --background --interval 1 --ntfy-topic papermerge-ojaswi
```

The command prints the permanent GitHub Pages URL and returns to the prompt.
The publisher runs in its own session with no SSH terminal dependency. You can
exit SSH or close the terminal; both the publisher and the detached training
supervisor keep running while the server remains up.

The private connection is stored under
`~/.config/papermerge/live-monitor/`, outside individual run directories. On the
first upgrade, an existing persistent `browser_share.json` in the selected run
is adopted so an already shared URL is preserved. Later runs reuse that same
connection. University servers with the same shared home reuse this state too.
Keep the private state directory when moving to a different home directory;
it contains the persistent publisher identity and is not tracked in Git.

For another run, execute the same command with its new `--output` directory.
An existing publisher follows the newly selected run rather than starting a
second uploader. Moving to another server updates the selected host: the old
publisher releases the shared lock and the new server takes over. The URL stays
the same. Completed/stopped snapshots remain visible, and the publisher waits
for a future selection without repeatedly uploading an unchanged terminal state.

To print the saved link again:

```bash
python scripts/share_cart_monitor.py --print-link
```

Only an old browser publisher for this exact output is stopped during the
upgrade. Process ownership, command, and output are checked before signaling
through a process descriptor; training processes are never targeted. No
training restart or checkpoint change is required.

## Status tabs and terminal parity

The page opens on **Running**, including workers that are starting. Select
**Pending** or **Completed** to see those configurations separately. A
**Failed / stopped** tab appears when needed; **All** shows every configuration
with running work first. Tab counts update every second, selected tabs survive
refreshes, and rows move between tabs as worker status changes.

The exact table columns are GPU, STATUS, DATA/SPLIT, SEED, SIGMA, ENV, CONDITION,
ROUND, ACTIVATIONS, ACC, ELAPSED, ETA. Formatting is checked against a fixture
generated by the terminal formatter. Header cards show elapsed wall time,
measured overall activations per second, remaining time, expected finish in
Eastern Time, active workers per GPU, pending/failed counts, clients, and rounds.
The dark layout supports desktop and mobile; the table scrolls independently
with sticky column headings.

Both the page and uploader use a one-second interval. Upload duration is
subtracted from the interval and slow requests do not overlap. Worker reporting
cadence is unchanged: polling does not invent new activation or accuracy
measurements. The page warns when a live feed has not updated for 45 seconds.

## Logs and sharing

```bash
tail -f ~/.config/papermerge/live-monitor/publisher.log
```

Ctrl+C closes only this log viewer. The background service stays running.
The publisher sends the link through ntfy after the first successful update
for a selection. Viewers need no SSH, VPN, or ChatGPT account.

Only allowlisted progress values are uploaded. Checkpoints, weights, examples,
source, logs, usernames, filesystem paths, process IDs, and raw errors are
excluded. The private write key has file mode 0600 and never appears in the
share URL or public API. Viewers cannot change the feed or control training.
The URL is unlisted rather than an authenticated viewer boundary.

`--temporary` remains an explicit legacy option for disposable links. Do not
use it for the permanent monitor: it intentionally creates a new expiring feed.
The progress API remains on the existing hosted service; the user-facing page
uses GitHub Pages. Existing persistent feed IDs and credentials remain valid.
